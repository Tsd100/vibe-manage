# 项目管理看板设计

日期：2026-09-05
状态：已确认的首版设计（暂以此开展）
范围：管理工作区与 Windows 开发版应用，不修改 `D:\Github` 下的业务仓库

## 1. 目标

看板要同时回答两个问题：

1. 每个项目是做什么的；
2. 每个项目现在推进到哪一步，以及下一步做什么。

首版采用“分组总览 + 项目详情页内嵌时间线”（A1）。首页适合快速筛选，详情页适合复盘单个项目。当前先实现可运行开发版，安装器和正式封装后置。

## 2. 总体架构

管理工作区分为四层：

1. **只读扫描层**：扫描 `D:\Github` 下的 Git 元数据、入口文档、工程清单、测试/CI 证据和文件时间；不写入被扫描仓库。
2. **注册表层**：以稳定的仓库相对路径作为项目 ID，合并自动字段、人工字段、验证结果和时间线事件。
3. **人工覆盖层**：保存用途、状态、阶段、优先级、下一步动作和手动修正时间；与自动扫描结果分离。
4. **看板层**：读取注册表和事件文件，提供总览、筛选、详情和时间线；首版不直接编辑业务仓库。

开发版使用 Windows 原生 Tkinter 窗口和 `pystray` 系统托盘。代码暂存于当前管理工作区，运行数据统一写入 `D:\Program Files (x86)\ProjectManagerData`。最终安装目录预留为 `D:\Program Files (x86)\ProjectManager`，但本阶段不制作安装包。

刷新方式采用手动触发：打开窗口时加载现有快照，点击“刷新”时执行一次只读扫描并更新 D 盘数据文件。首版不启用常驻后台或定时任务。

窗口关闭行为：点击关闭按钮时隐藏窗口并保留托盘图标；托盘菜单提供“打开看板”和“退出应用”。只有点击“退出应用”才结束进程。

## 3. 项目数据模型

每个项目至少包含以下字段：

- 标识：`id`、`path`、`name`；
- 说明：`purpose`、`purpose_source`；
- 人工管理：`manual_status`、`manual_phase`、`manual_priority`、`next_action`；
- Git/文件证据：`created_at`、`created_at_source`、`last_commit_at`、`working_tree_modified_at`、`last_modified_at`、`branch`、`dirty_files`；
- 验证证据：`validation.status`、`validation.summary`、`validation.command`、`validation.observed_at`；
- 可追溯性：`observed_at`、`evidence[]`、`timeline[]`。

### 时间字段规则

- `created_at` 优先取首个 Git 提交时间；
- 没有 Git 提交时取最早源文件时间，并将 `created_at_source` 标记为 `filesystem_estimate`；
- 两类时间都不可靠时显示“未知”，允许人工补录；
- 人工修正写入 `manual_created_at`，保留自动值和原始来源；
- `last_modified_at` 是 Git 最近提交时间与工作树最后修改时间中的较新者，但两者始终单独展示。

## 4. 首页与详情页

### 首页：分组总览

左侧提供按人工状态、阶段和自动关注信号的筛选；主区显示项目卡片。卡片至少显示用途摘要、阶段、状态、下一步动作、最近修改时间和验证等级。

自动关注信号包括：有未提交修改、长期未活动、测试未验证、环境阻塞、用途待确认。

### 详情页：基本信息 + 时间线

顶部显示用途、状态、阶段、优先级、下一步动作和三类时间：创建时间、最近提交时间、工作树最后修改时间。下方按时间倒序显示提交、工作树改动、验证结果和人工备注；每条事件显示时间、类型、摘要和来源。

## 5. 状态与证据边界

人工状态枚举为：未开始、进行中、已完成、阻塞、暂停、归档。人工阶段枚举为：探索、规划、开发、验证、维护。

证据等级为：无证据、文件证据、测试通过、运行验证。自动字段只能作为线索，不能自动把项目标记为“已完成”；人工确认和可复现验证必须分别保留。

## 6. 错误处理

- 仓库不是 Git：保留项目记录，Git 字段为空，显示文件时间或未知；
- 缺少依赖：验证状态为“环境阻塞”，记录完整错误文本和命令；
- 测试入口路径不一致：记录实际可复现命令，不修改项目配置；
- 扫描单个项目失败：保留上一次快照，在项目上显示“本次刷新失败”，其他项目继续更新；
- 路径变化：通过路径变更记录或人工确认合并，禁止静默创建重复项目。

## 7. 首版验收标准

1. 能展示 38 个项目，并排除 2 个参考仓库的工作看板；
2. 任一项目详情页能同时看到用途、阶段、下一步、创建时间和最后修改时间；
3. 无 Git 提交时间的项目不会报错，并能显示估算/未知及人工修正入口；
4. 时间线至少能展示最近提交、工作树改动和验证事件；
5. 点击刷新不会修改任何业务仓库；
6. 扫描失败、依赖缺失和验证未执行均有明确状态，而不是显示为“完成”；
7. 注册表、扫描快照和人工覆盖文件可以独立备份与恢复。

## 8. Windows 开发版与数据目录

数据目录至少包含：

- `inventory/`：扫描快照和项目注册表；
- `overrides/`：人工用途、状态、阶段、优先级、下一步和手动时间修正；
- `timeline/`：按项目保存的事件记录；
- `logs/`：刷新错误、权限错误和应用运行日志。

应用启动时检查 `D:\Program Files (x86)\ProjectManagerData` 是否可读写。若权限不足，窗口显示明确错误和目录路径，不静默改写到 C 盘；开发版允许通过环境变量或启动参数指定临时数据目录用于测试。

## 9. 非目标

首版不做安装包、代码签名、开机自启、后台定时任务、跨机器同步、自动提交/清理 Git、自动判断业务完成度、网络抓取项目文档，也不把参考仓库混入项目进度统计。

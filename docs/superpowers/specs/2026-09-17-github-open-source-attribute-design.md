# GitHub 开源属性设计

## 目标

为每个项目增加“是否开源到 GitHub”属性。扫描时根据项目 Git remote 自动给出判断，用户可在编辑窗口手动覆盖；详情页、搜索和项目时间线都能看到这个状态，同时保留远程地址作为判断依据。

## 采用方案

采用“Git remote 自动判断 + 人工覆盖”的单一属性方案，不在项目列表增加新列，以保持现有布局宽度和可读性。

### 状态与来源

每个项目记录包含以下字段：

- `github_open_source`：当前生效值，取 `是`、`否` 或 `未确认`。
- `manual_github_open_source`：人工覆盖值，允许为空；为空表示跟随自动判断。
- `github_open_source_source`：当前值来源，取 `auto_git_remote` 或 `manual`。
- `github_remote_url`：扫描到的 GitHub remote 地址；没有 GitHub remote 时为空。

自动判断规则：

1. 能成功读取 Git remote，且任一 remote 的主机为 `github.com`（兼容 HTTPS、SSH、scp-like 写法）时，自动值为 `是`，并记录该地址。
2. Git remote 命令执行成功但没有 GitHub 地址时，自动值为 `否`。
3. Git 不可用、命令失败或仓库状态无法读取时，自动值为 `未确认`，不把失败误判为未开源。
4. 该判断只证明项目连接到 GitHub，不调用 GitHub API 判断仓库公开/私有；私有仓库可由用户手动改为 `否`。

人工覆盖的优先级高于自动值。编辑窗口选择 `未确认` 时保存为空覆盖并恢复自动判断；选择 `是` 或 `否` 时保存对应人工值。重新扫描不会覆盖人工值，但会更新自动判断和 remote 地址。

## 数据流与兼容

扫描器读取每个仓库的 remote，将自动字段写入扫描记录；现有人工覆盖通过已有 overrides 存储合并。旧注册表缺少新字段时按 `未确认`、`auto_git_remote` 和空 remote 兼容读取，下一次扫描会补齐字段。已有项目 ID、路径、创建时间、最后修改时间及其他人工字段保持不变。

## 界面行为

- 项目详情面板增加“GitHub 开源”字段，显示当前生效值；若有 remote，在值下方显示 GitHub 地址。
- “编辑人工字段”对话框增加“GitHub 开源”只读下拉框，选项为 `未确认`、`是`、`否`。当前为自动判断且无覆盖时显示自动值，但保存 `未确认` 会清除覆盖。
- 项目总览的搜索框可匹配当前开源状态、remote 地址和项目原有文本；不增加列表列，避免破坏用户已经调整好的列宽。
- 项目时间线增加一条“GitHub 开源状态”人工事件，记录当前生效值、来源和 remote 地址；保存人工覆盖时追加一条带保存时间的人工事件，避免重复扫描产生重复事件。

## 时间线持久化

现有项目时间线文件继续由扫描器生成基础 Git/文件系统事件。人工开源状态变更追加到同一项目时间线文件，并在下一次扫描时保留；事件包含 `at`、`event_type=github_open_source`、状态变化摘要和 `source=manual` 或 `auto_git_remote`。如果历史文件不存在，保存时创建它。加载旧事件时保持原有排序规则，未知时间仍排在有时间事件之后。

## 错误处理

- remote 地址解析失败只影响 GitHub 属性，不阻断整个项目扫描。
- remote 命令超时或 Git 不可用显示“未确认”，并允许人工选择。
- overrides 文件损坏沿用现有错误处理，不静默删除用户数据。
- UI 保存后立即刷新详情、搜索结果和时间线；取消不改变任何数据。

## 验证标准

1. 测试 HTTPS、SSH 和 scp-like GitHub remote 均识别为 `是`，非 GitHub remote 为 `否`，命令失败为 `未确认`。
2. 测试没有提交的仓库仍能扫描并得到开源属性默认值。
3. 测试人工 `是/否` 覆盖优先于自动值，清除覆盖后恢复自动值，重新扫描不丢失覆盖。
4. 测试详情字段、搜索匹配、编辑下拉选项和时间线人工事件。
5. 运行完整测试套件，确认现有项目总览、时间线、扫描记录、设置、托盘和图标功能不回归。
